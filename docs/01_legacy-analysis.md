## 2. クエストバトル仕様（`GameDirector.cs` ほか）

### 2.1 基本の流れ
- 敵の行動は **クエストごとに固定の配列**（`enemyTurns`、1〜36 ターン）。**乱数なし・完全決定論**。
- 最終ターンの敵行動は必ず **「必殺技」= 攻撃力 × 100 ダメージ（実質即死）**。
  → **最終ターンまでに倒すタイムアタック**。これが「最終ターン」の正体。
- 1 ターンの処理順: **敵が先に行動 → プレイヤーの行動**。
  ただし **防御・防御バフ・必殺技は「先制コマンド」**で敵より先に効く。
- 敵 HP 0 で勝利、プレイヤー HP 0 で敗北。`ChangeQuestName` があれば連戦（例: I → I2）。

### 2.2 プレイヤーコマンド（全 7 種 + 補助）

| コマンド | 効果 | ターン消費 |
|---|---|---|
| 攻撃 | `max(0, ATK × 攻撃倍率 − 敵DEF)` のダメージ | ○ |
| 防御（先制） | 今ターン受けるダメージを大幅軽減（下式） | ○ |
| 攻撃バフ | 攻撃倍率 += キャラの `PvpAttackBuffRate`（初期 1.0、加算） | ○ |
| 防御バフ（先制） | 防御加算 = 回数 × キャラの `PvpDeffenceBuffAmount` | ○ |
| チェック | 現在ターンをチェックポイントに登録（最大 `PvpCheckMaxCount`=2、同ターン不可、1ターン目不可） | × |
| リターン | チェックポイントのターンへ戻る（最大 `PvpReturnMaxCount`=1）。戻るとチェックポイントは全消去 | × |
| 必殺技（先制） | 条件を満たすと、**前後 2 ターン（計 5 ターン）の敵行動を見て、そのうち 1 ターンを 攻撃/防御/攻撃バフ/防御バフ/挑発 に書き換え**（最大 1 回） | × |
| みえーるみえーる | 敵の全行動パターンを **10 秒間表示**。回数はクエストごと（`DisclosureEnemyTurnCount` 1〜3） | × |
| ログ | ステータス・最終ターン・行動履歴の確認 | × |

**必殺技の発動条件（全て満たす）**: ①リターン 1 回以上 ②HP が最大の半分未満 ③3 ターン目以降 ④最終ターンの 3 ターン以上前（`2 < Turn < MaxTurn − 2`）

### 2.3 ★リターンの正体（リメイクで一番大事な仕様）
`ChoiceCheckPointManager.ChoiceCheckBtn()` で巻き戻るのは **ターン番号と敵の行動ポインタだけ**。
**プレイヤー/敵の HP・バフ・デバフ・属性は巻き戻らない。**

= 「与えたダメージと積んだバフを持ったまま、敵の行動スケジュールだけを過去に戻す」システム。
- 最終ターン（敵の必殺技）を先送りでき、実質的に持ち時間が延びる
- 敵がガードや集中をしている「攻めどき」の区間をもう一度やり直せる
- 敵にとって有利な区間（連続攻撃など）を繰り返すリスクもある

### 2.4 ダメージ・効果の計算式

| 項目 | 式 |
|---|---|
| 属性補正 | 陽(YANG) > 音(NOTE) > 月(MOON) > 陽。有利側は自ATK×1.25・相手ATK×0.75（不利側はその逆） |
| プレイヤー攻撃 | `max(0, ATK補正後 × 攻撃倍率 − 敵DEF現在値)` |
| 敵の通常攻撃 | `max(0, 敵ATK補正後 × 敵攻撃倍率 − (自DEF + 防御バフ加算))` |
| プレイヤー防御 | 受けるダメージ = `max(0, 敵攻撃 × 0.2 − 自DEF − 防御バフ加算)`（実装上は一時的に DEF を上げる） |
| 敵の防御 | そのターンの敵DEF = `自ATK × 攻撃倍率 × 0.8` → **与ダメが 2 割に減る** |
| 敵 攻撃バフ | 敵攻撃倍率 += `QuestAttackBuffRate`（ほぼ 0.5） |
| 敵 防御バフ | 敵DEF += `QuestDeffenceBuffAmount`（永続） |
| 敵 強攻撃 | `QuestStrongAttackPower − 自DEF合計`（防御可能） |
| 敵 固定攻撃 | `QuestFixedAttackPower` の固定ダメージ（防御不可） |
| 敵 集中 | 何もしない（強攻撃・固定攻撃の前振り）→ 攻めどき |
| 敵 挑発 | 敵ATK +10 のみ（実質攻めどき） |
| 敵 全回復 | HP を最大値まで回復 |
| 敵 超回復 | HP += 最大HP × `QuestRecoveryRate`。最大値を超えたら最大HPも上がる |
| 敵 属性変化 | 元の属性 ⇔ `QuestChangeAttribute` を切り替え（BGM も変わる） |
| 敵 ビリビリ | 3 ターンの間、プレイヤー行動が **50% で不発**（ビリビリ耐性キャラは無効） |
| 敵 攻撃デバフ | 自攻撃倍率 −= `QuestAttackDebuffCount`（下限 0） |
| 敵 防御デバフ | 防御バフ回数 −= `QuestDefenceDebuffCount` |
| 敵 必殺技 | `敵ATK × 敵攻撃倍率 × 100` |

※ スピードはクエストでは使われない（PvP の行動順だけで使う）。
※ `Quest.GetEnemyDefenceDebuffCount()` が **攻撃デバフ値を返すバグ**あり。
※ ビリビリの抽選は `DateTime.Now.Millisecond` をシードにした非決定的乱数。

## 3. 15thクノット（PvP）仕様（`KimeteGameDirector.cs` ほか）

- **事前に 15 ターン分の行動を編成**（ターン編成画面）。選べるのは 攻撃 / 防御 / 攻撃バフ / 防御バフ / スピードバフ + キャラ固有の**ギミック**（最大 3）。
- 対戦中は編成した行動が順に実行される。プレイヤーが割り込めるのは **チェック / リターン / 必殺技** だけ。
- 行動順: 防御・挑発が先制。それ以外は `SPD × スピード倍率` が高い方が先。同速ならホストが順番を決めて送る。
- 自分の必殺技では、相手の 5 ターン分の編成を見て 1 ターン書き換える（相手へのリクエストとレスポンスで実現）。
- 通信: GS2 Matchmaking でマッチング → GS2 Chat のルームを**メッセージ中継に流用**（ターンごとに `category` 番号で種類を判別: 行動=ターン番号, 順番決め=200+, リターン=300+, 必殺技の要求=400+, 必殺技の内容=600+, ランク情報=1000）。
- ランクマッチ: 4級ノ壱〜特級〜妖怪級。1000pt ごとに昇格。シーズン制（GS2 Schedule）。ポイントランキングあり（GS2 Ranking）。
- ※ コード中に「要確認」やコメントアウトが多く、**未完成**（記事でも「マッチング人口不足」と指摘）。
- ※ 対戦の判定が両方のクライアント側で行われ、サーバは中継だけなので**チート耐性がない**。

## 4. 育成・経済

### 4.1 ステータス計算（`Character.cs`）
```
HP  = 基礎HP  + 42×HPアイテム数  + 14×HP被り数  + 天気HP
ATK = 基礎ATK + 18×ATKアイテム数 +  8×ATK被り数 + 天気ATK
DEF = 基礎DEF +  2×DEFアイテム数 +  2×DEF被り数 + 天気DEF
SPD = 基礎SPD +  1×SPDアイテム数 +  1×SPD被り数 + 天気SPD
```
- アイテム使用上限: HP 20 / ATK 16 / DEF 15 / SPD 10（全キャラ共通）
- 被り上限: キャラごと（例: A は HP40 / ATK24 / DEF15 / SPD10）。被るたびに上限に達していないステータスからランダムで 1 つ +1。
- ※ **育成データは端末ローカルに JSON 保存**（`SaveManager`）→ 機種変更で消える・改ざんされうる。リメイクではサーバ保存にするべき。

### 4.2 アイテム（12 種 = 3 属性 × 4 ステータス）
| 属性 | 名前 | 種類 |
|---|---|---|
| 陽 YANG | 〜の灯 | HP / ATK / DEF / SPD |
| 音 NOTE | 〜の譜 | 同上 |
| 月 MOON | 〜の酒 | 同上 |
- 入手先はお天気クエストや広告報酬。対応する属性のキャラにしか使えない。

### 4.3 天気（日替わり）
- 1 日 1 回、重み付き抽選（12 種、晴・曇・雨は重み 2、それ以外は 1）。
- **天気と同じ属性のキャラ**に天気のボーナスが付く（例: 晴=陽 ATK+60、雪=音 HP+200、嵐=月 DEF+15）。
- 天気ごとに**お天気クエスト**が 1 つ開放される（強化アイテムのドロップ用）。

### 4.4 レベル・報酬
- メインクエストを**初めてクリアすると Lv+1**。挑戦できるメインクエスト数 = Lv。
- Lv が偶数になったときに**お札**がもらえる（`QuestFirstClearBonus`）。
- クエストをクリアすると、出てきたキャラが**確率で仲間になる**（具体的な確率は GS2 側にあり、ソースには無い）。
- Lv9 で PvP 解禁。

### 4.5 お札の入手と使い道
- 入手: ログインボーナス +1 / 偶数Lv到達 / 広告視聴（抽選でお札・アイテム・キャラ）/ 課金
- 使い道: ノーマルガチャ（5 枚、ガチャ限定キャラあり）
- 課金: ¥120=2枚 / ¥250=6枚 / ¥490=12枚 / ¥1100=30枚 / ¥2080=60枚 / ¥3180=100枚（UI表記からの推定）

## 7. リメイクに向けた所見

### 残したいもの（ゲームの核）
1. **決定論的な敵パターン + リターン（HP・バフを持ったまま時間を戻す）**。旧作最大の独自性。
2. 必殺技による「敵の行動を 1 ターン書き換える」逆転要素。
3. 最終ターンの即死必殺技によるタイムリミット。
4. 3 すくみ属性 × 日替わり天気 × お天気クエストの周回。
5. 手書き風の妖怪モチーフのアート（素材はプロジェクト内に全部ある）。

### 直したいもの（技術・設計）
| 旧作の問題 | リメイクでの方針 |
|---|---|
| バトルロジックが UI（MonoBehaviour）と密結合。3,900 行の `GameDirector` | **バトルエンジンを純粋な関数として分離**（状態 + コマンド → 次の状態）。フロントとサーバで同じルールを使える形にする |
| 育成データ・お札がローカル保存（ObscuredPrefs） | サーバに持たせて正とする |
| PvP の判定がクライアント任せ | サーバで判定する（Kotlin バックエンドの一番の見せ場） |
| マスタデータが GS2 にあって消えた | マスタは**リポジトリで管理**する（JSON/YAML → DB へ投入） |
| 敵行動の配列が 100 個の enum フィールド | 配列 / JSON に正規化 |
| 乱数が時刻シード | シード付きの乱数にしてリプレイ・検証をしやすくする |

### 抽出できなかった情報（オーナーの記憶か再設計が必要）
- クエストのクリア報酬テーブル（どのキャラがどの確率で仲間になるか）
- ガチャの提供割合（`NormalGcya`）
- メインクエストの正確な解放順（GS2 のメタデータ `MainQuestNo`）
- 広告報酬の抽選表、ランクマッチの報酬
- イベントの開催スケジュール
