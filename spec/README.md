# spec

web（AI）と api（オーナー）の約束事。**ここに書かれたものが唯一の正**。

| ディレクトリ | 内容 | 状態 |
|---|---|---|
| `battle/` | クエストバトルのルールとゴールデンテスト（api のエンジンが通す。D-8） | v0.5・ケース 15 件 |
| `openapi/openapi.yaml` | API の定義（OpenAPI 3.1）。エラーは RFC 9457 の形 ＋ `code`。各 API の説明は今の仕様だけを書き、変更の記録は `info.description` の「変更履歴」に書く | 0.4.0（認証・`/me`・`/app/version`・所持キャラ・今日の天気・クエスト・バトル） |
| `master/` | マスタデータ（属性・キャラ・クエスト・天気・アイテム・設定）。api の各モジュールが自分の分を jar に同梱して読む。まとめては配信しない（`docs/05` §7・D-8） | 初版（旧作から移行） |
| `tools/validate.py` | spec 全体の検証（スキーマ・相互参照） | — |

## 検証
```bash
pip install jsonschema
python3 spec/tools/validate.py
```

## 変更のルール
1. AI が下書きする（または変更を提案する）。
2. **オーナーがレビューして確定する。**
3. web と api は、spec が通るまで実装を直す。**実装に合わせて spec を書き換えない。**
4. spec が間違っていると思ったら、実装を変える前にオーナーに相談する。
